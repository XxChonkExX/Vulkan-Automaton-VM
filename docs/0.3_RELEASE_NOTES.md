# v0.3.0 Release Notes (draft)

> Positioning: **Core + verified multi-vendor local + basic networked
> transport, with honest limitations.** Not a production multi-node fabric.

## Headlines

- **Standalone Chonk Buffer**: the core memory pool builds with zero network
  dependencies (`VVM_BUILD_CORE_ONLY=ON`). Layered architecture with
  namespaced CMake aliases: `VulkanVM::Core`, `VulkanVM::Transport`,
  `VulkanVM::Compute`.
- **Chonk allocator hardening**: exact-fit grants (power-of-2 rounding waste
  eliminated), aligned grants, internal-waste metric, concurrent stress
  tested, and a dedicated CPU-only invariant/fuzz suite
  (`tests/chonk_slab_test.cpp`) covering boundary sizes, double-free,
  overlap tracking, and provider-failure recovery.
- **llama.cpp integration at parity**: one 40B model pooled across an AMD
  RX 7900 XTX and an Intel Arc Pro B70 — worst case −2% vs stock
  (docs/inference_benchmarks.md), with `--vvm-split` tensor placement and a
  live `/vvm/stats` endpoint.
- **Android verified**: AHardwareBuffer import end-to-end on Galaxy S24+
  (Adreno, API 36).
- **Audit-driven correctness pass** (two external audits + response):
  escalation size-mismatch fix, negative-size ABI rejection, TLS ALPN
  ownership, module split, device-selection policy, normative
  [lifetime contract](LIFETIME_CONTRACT.md), [threat model](THREAT_MODEL.md),
  and an evidence-linked [hardware matrix](HARDWARE_SUPPORT.md).
- **CI**: compile matrix (Linux GCC/Clang, Windows MSVC, Android NDK) +
  CPU-only regression suites on every push.

## Security posture (read this)

The wire parser is hardened (magic/version/type checks, absolute size caps).
As of 0.3.0 the following network hardening **has shipped**: 30 s socket
timeouts on accepted connections, a concurrent-connection cap
(`netConfig.maxConnections`, default 64), and chunked body reads (buffers
grow only as bytes arrive — a declared-but-unsent body no longer forces an
up-front host allocation). Still open per
[THREAT_MODEL.md §5](THREAT_MODEL.md#5-hardening-roadmap-03): per-source
accept rate limiting, cluster membership authorization, wire-parser fuzzing.
**Deploy on trusted networks or behind access control.**

## Known limitations

- NVIDIA: designed, not validated (no hardware).
- Android: verified on Adreno only.
- ONNX provider: CPU fallback.
- Autograd ops execute through ATen; Vulkan dispatch landing; numerical
  suite in `test_autograd_numerics.py`.
- `.*=auto` tensor placement on very large models can hit an upstream
  ggml-vulkan upload-path exception; use scoped patterns.

## Upgrade notes

- `VVM_BUILD_CORE_ONLY=ON` replaces the manual NETWORK/TENSOR/PYTORCH/ONNX
  off-dance (still supported).
- Windows SDK is now auto-detected (newest SDK with a complete toolchain);
  override with `CMAKE_SYSTEM_VERSION` / `VVM_RC_COMPILER` / `VVM_MT`.
- Training scripts take repo-relative defaults; configure via
  `CHONK_MODEL_PATH` / `CHONK_DATA_PATH` / `CHONK_OUT_DIR` /
  `CHONK_STATUS_FILE`.
- Core API surface is frozen for 0.3.x per
  [docs/LIFETIME_CONTRACT.md](LIFETIME_CONTRACT.md); transport evolves under
  the versioned wire protocol (docs/WIRE_PROTOCOL_VERSIONING.md).

## Verification gates passed

- Core-only and full-stack builds green on MSVC (CI covers Linux GCC/Clang)
